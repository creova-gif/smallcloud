## Vision

### 10x Check
SmallCloud delivers 10x value for <2x effort by turning its in-memory control-plane primitives into a persistent, transactional micro-SaaS runtime:
1. Full HTTP control plane (`POST /v1/deploy`, `POST /v1/rollback`, `GET /v1/status`, `POST /v1/meter`), persistent `state.json` (`DaemonState`), and CLI `init`, `status`, `budget` (including `budget set`) commands (`SURFACE-GAP-1`).
2. Transactional Litestream SQLite WAL checkpointing (`SyncWAL` / `Restore` with `.sha256` sidecar verification) automatically wired into every Blue/Green `Deploy`, `Rollback`, and budget `onHalt` (`EXP-1`), resolving container `/data/...` paths against the daemon's host data root when needed.
3. Live budget top-up and instant route unhalting (`onUnhalt` -> `ResumeRoute` + `BudgetEvent` audit log) when `max_monthly_usd` is raised via `smallcloud budget [set]` or `POST /v1/meter` (`EXP-2`).
4. Pluggable `ProxyApplier` (`HTTPAdminApplier` for live Caddy `/load` reloads with automatic rollback on HTTP 4xx/5xx, plus `NoopApplier` default for deterministic tests) (`EXP-3`).

### Platonic Ideal
An indie builder runs `smallcloud init [dir] [--force]` inside any FastAPI, Go, or Node repo to generate a validated `smallcloud.toml` with a `$5.00` hard spend cap. Running `smallcloud deploy` checkpoints the active SQLite WAL (`SyncWAL` with `.sha256` sidecar if the host DB exists) and restores verified replica state (`Restore`) into the target host DB path if the local DB is missing, applies Linux cgroups v2 quotas (`cpu.max`, `memory.max`), and atomically swaps Caddy in `<10ms`. When a runaway loop hits `$5.00`, SmallCloud's in-proxy meter flushes a final SQLite WAL snapshot, halts the route with `HTTP 402`, and records a `BudgetEvent`; raising the cap via `smallcloud budget [set] [dir] <max_monthly_usd>` or `POST /v1/meter` immediately unhalts the route without redeploying.

## Accepted Scope (added to this plan)
- `SURFACE-GAP-1` (Option A): `daemon/server.go` (`POST /v1/deploy`, `POST /v1/rollback`, `GET /v1/status`, `POST /v1/meter`), atomic `state.json` (`DaemonState`) load/save in `stateDir`, and CLI `init`, `status`, `budget` (`smallcloud budget [set] [dir] [max_monthly_usd]`) commands in `cli/cli.go`.
- `EXP-1` (Option A): Automatic `StorageManager.SyncWAL` / `Restore` wired into `Daemon.Deploy`, `Daemon.Rollback`, and budget `onHalt`, storing per-app resolved host `SQLitePath` in `DaemonState` and attaching `LastSnapshot *SnapshotMetadata` to `DeploymentResult` and `/v1/status`.
- `EXP-2` (Option A): `onUnhalt` callback on `BudgetTracker` calling `CaddyRouter.ResumeRoute(orgID, appName)`, `BudgetEvent` audit history, and live budget cap updates via `smallcloud budget [set]` and `POST /v1/meter`.
- `EXP-3` (Option A): `ProxyApplier` interface and `HTTPAdminApplier` (`POST /load` with 2s timeout) in `daemon/proxy.go` that automatically reverts in-memory Blue/Green state if Caddy returns HTTP 4xx/5xx.
- `SEC-HARDEN-1` (Option A): `math.IsNaN`/`math.IsInf` guard in `BudgetTracker.RecordSpend`, strict slug/domain/healthcheck/path-clean validation across `pkg/config` and `daemon/`, and `.sha256` sidecar verification before `os.Rename` in `StorageManager.Restore`.
